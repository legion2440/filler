# Filler

Игрок на Rust для алгоритмической игры **01 Edu Filler** со строгой проверкой постановки фигур, стратегией контроля территории, встроенным **Live Visualizer** и браузерным **Replay Lab**.

Игрок читает официальный протокол `game_engine` из `stdin` и на каждом ходу пишет в `stdout` ровно одну команду `X Y\n`.

## 🎮 Суть игры за минуту

Filler — пошаговая игра на захват свободной площади для двух ботов.

- У каждого игрока есть стартовая территория на поле Anfield.
- На каждом ходу `game_engine` выдаёт случайную фигуру.
- Фигура должна перекрывать **ровно одну** уже занятую клетку своей территории.
- Перекрывать клетки противника нельзя.
- Все занятые клетки фигуры должны оставаться внутри поля.
- Остальные занятые клетки поставленной фигуры становятся новой территорией игрока.
- Прямого захвата или перекрашивания чужих клеток нет.
- Тактика строится на расширении, блокировании направлений роста противника и отсечении свободных зон.
- В конце выигрывает игрок, занявший больше клеток.

Player 1 обозначается `@` / `a`, Player 2 — `$` / `s`. Строчные символы показывают клетки последней поставленной фигуры.

## 🚀 Быстрый старт

### Требования

- Rust `1.63+`
- Cargo
- Docker Desktop / Docker Engine
- современный браузер для визуализатора
- `make` необязателен, но удобен

Клонирование:

```bash
git clone https://github.com/legion2440/filler.git
cd filler
```

Unit-тесты:

```bash
cargo test
```

Release-сборка игрока под текущую ОС:

```bash
cargo build --release --bin filler
```

Для обычной разработки и аудитных прогонов удобнее запускать встроенный Visualizer:

```bash
make visualizer
```

или без `make`:

```bash
cargo run --bin visualizer
```

Локальный сервер открывает `http://127.0.0.1:8080`, находит официальный пакет Filler, подготавливает Linux-версию Rust-игрока внутри Docker, запускает выбранные матчи, передаёт их в браузер в live-режиме и автоматически сохраняет реплеи.

## 🐳 Официальное игровое окружение

`game_engine`, карты и штатные роботы **не входят в этот репозиторий**. 01 Edu распространяет их отдельным архивом.

Скачать архив:

```text
https://assets.01-edu.org/filler/filler.zip
```

Распакуйте его **рядом** с репозиторием и назовите папку `filler-engine`:

```text
TSchool/
├── filler/                  <- этот репозиторий
│   ├── src/
│   ├── tests/
│   ├── visualizer/
│   └── ...
│
└── filler-engine/           <- официальный архив 01 Edu
    ├── Dockerfile
    ├── linux_game_engine
    ├── linux_robots/
    ├── m1_game_engine
    ├── m1_robots/
    ├── maps/
    └── solution/
```

Visualizer автоматически ищет:

```text
../filler-engine
```

Если официальный пакет лежит в другом месте:

```bash
cargo run --bin visualizer -- --engine-dir "D:\path\to\filler-engine"
```

или:

```bash
FILLER_ENGINE_DIR=/path/to/filler-engine make visualizer
```

Docker должен быть запущен. При первом нажатии **Start** Rust-сервер автоматически:

1. проверяет наличие `Dockerfile`, `linux_game_engine`, `linux_robots/` и `maps/`;
2. собирает официальный Docker-образ `filler`, если его ещё нет;
3. монтирует текущий репозиторий в `/filler/solution`;
4. компилирует игрока **внутри официального Linux-контейнера на Rust 1.63** в отдельный `target/docker-linux`;
5. запускает `linux_game_engine` с выбранной картой, противником и стороной;
6. передаёт вывод движка в браузер через SSE;
7. сохраняет полный сырой лог матча в `replays/`.

Так не возникает проблемы с Windows-бинарником внутри Linux-контейнера и не требуется ручная кросс-компиляция.

## 🖥️ Live Visualizer

Запуск:

```bash
make visualizer
```

Панель **Run match** позволяет выбрать:

- карту из реальной папки `maps/`;
- противника из `linux_robots/`;
- сторону `P1`, `P2` или чередование сторон;
- от `1` до `20` матчей в серии;
- случайный или фиксированный seed;
- включение/выключение live-визуализации;
- Start / Stop;
- готовые аудитные пресеты.

Пресеты:

| Пресет | Карта | Противник | Матчей | Сторона |
| --- | --- | --- | ---: | --- |
| `wall_e audit` | `map00` | `wall_e` | 5 | alternate |
| `h2_d2 audit` | `map01` | `h2_d2` | 5 | alternate |
| `bender audit` | `map02` | `bender` | 5 | alternate |
| `terminator bonus` | `map01` | `terminator` | 5 | alternate |

Основное поле, Play/Pause, шаг назад/вперёд, переход в начало/конец, timeline и скорость воспроизведения находятся непосредственно под доской и остаются в основном рабочем экране. Вёрстка рассчитана на нормальную работу при **100% масштабе браузера** на обычном настольном мониторе. График роста территории вынесен ниже основной зоны матча.

### Режим только для реплеев

`visualizer/index.html` можно открыть напрямую с диска. Тогда работают импорт файлов, воспроизведение и локальная библиотека реплеев, но запуск Docker-матчей и Live SSE недоступны, потому что Rust-сервер не запущен.

## 🧪 Ручной запуск через Docker

Visualizer — основной удобный способ. Ниже приведён полностью ручной сценарий, который можно использовать при аудите или отладке.

### 1. Собрать официальный Docker-образ

Из папки распакованного официального движка.

**Windows Git Bash**

```bash
cd /d/TSchool/filler-engine
docker build -t filler .
```

**WSL / Linux**

```bash
cd /mnt/d/TSchool/filler-engine
docker build -t filler .
```

Предупреждение Docker о shell-form `ENTRYPOINT` относится к предоставленному 01 Edu Dockerfile и само по себе не мешает сборке.

### 2. Зайти в контейнер и примонтировать репозиторий

**Windows Git Bash**

```bash
docker run --rm -it \
  -v "D:/TSchool/filler:/filler/solution" \
  filler
```

**WSL / Linux**

```bash
docker run --rm -it \
  -v /mnt/d/TSchool/filler:/filler/solution \
  filler
```

После этого приглашение командной строки уже относится к контейнеру, например:

```text
root@...:/filler#
```

### 3. Собрать Rust-игрока внутри контейнера

Следующие команды выполняются **внутри контейнера**:

```bash
cd /filler/solution
CARGO_TARGET_DIR=target/docker-linux cargo build --release --bin filler
cd /filler
```

Исполняемый файл будет находиться здесь:

```text
/filler/solution/target/docker-linux/release/filler
```

### 4. Запуск матчей внутри контейнера

Против `wall_e`:

```bash
./linux_game_engine \
  -f maps/map00 \
  -p1 /filler/solution/target/docker-linux/release/filler \
  -p2 linux_robots/wall_e
```

Против `h2_d2`:

```bash
./linux_game_engine \
  -f maps/map01 \
  -p1 /filler/solution/target/docker-linux/release/filler \
  -p2 linux_robots/h2_d2
```

Против `bender`:

```bash
./linux_game_engine \
  -f maps/map02 \
  -p1 /filler/solution/target/docker-linux/release/filler \
  -p2 linux_robots/bender
```

Бонусный `terminator`:

```bash
./linux_game_engine \
  -f maps/map01 \
  -p1 /filler/solution/target/docker-linux/release/filler \
  -p2 linux_robots/terminator
```

Чтобы проверить вторую сторону, поменяйте значения `-p1` и `-p2` местами.

## 🧠 Алгоритм игрока

Rust-реализация разделяет парсинг протокола, проверку легальности и стратегию, чтобы критические правила можно было тестировать независимо.

Каждый ход выполняется так:

1. парсится Anfield и входящая фигура;
2. занятые клетки фигуры сохраняются как координаты;
3. возможные origins генерируются совмещением каждой занятой клетки фигуры с каждой собственной клеткой на поле;
4. дубликаты кандидатов удаляются;
5. нелегальные постановки отбрасываются;
6. строится multi-source distance field от территории противника;
7. все легальные ходы получают быстрый score;
8. лучшие кандидаты проходят глубокую оценку;
9. выбирается детерминированно лучший ход и выводится `X Y\n`;
10. `stdout` немедленно flush-ится, поскольку `game_engine` работает интерактивно.

Такой генератор кандидатов не перебирает вслепую каждую возможную левую верхнюю координату фигуры по всему полю.

## ✅ Правила постановки

`validate_placement` не зависит от стратегии и проверяет только правила игры:

- `0` пересечений со своей территорией → invalid;
- ровно `1` своё пересечение → valid, если остальные условия соблюдены;
- `2+` своих пересечений → invalid;
- любое пересечение с противником → invalid;
- любая занятая клетка фигуры за пределами поля → invalid.

Учитываются только занятые клетки фигуры. Пустой padding из `.` может формально выходить за границу, если все занятые клетки остаются внутри Anfield. Парсер принимает как `O`, так и `#`: любая клетка фигуры, отличная от `.`, считается занятой.

## 🎯 Стратегия

Стратегия — детерминированная двухэтапная эвристика, перенесённая с ранее настроенного варианта алгоритма.

### Быстрая оценка

Для каждого легального хода учитываются:

- минимальная дистанция новых клеток до противника;
- суммарная дистанция до противника;
- давление возле вражеской территории;
- количество новых frontier-клеток для дальнейшего расширения;
- количество новых занятых клеток;
- лёгкие поправки за край поля и положение относительно центра.

Пока территории далеко друг от друга, сильнее весится сближение с противником. Когда контакт уже близок, больший вес получает контроль территории и frontier.

### Глубокая оценка

Лучшие кандидаты после быстрого scoring дополнительно оцениваются по:

- прогнозируемому контролю свободной территории по distance field;
- размеру собственного frontier;
- размеру frontier противника после постановки.

В глубокую фазу попадают только лучшие `72` кандидата, чтобы ограничить стоимость одного хода. При равных score используется детерминированный порядок координат, поэтому seeded-прогоны можно сравнивать между собой.

## 🧪 Тесты

Запуск:

```bash
cargo test
```

`tests/core.rs` покрывает требования задания и audit sheet:

- парсинг `p1` и `p2`;
- размеры и строки Anfield;
- размеры и занятые клетки фигуры;
- валидную постановку с ровно одним своим пересечением;
- запрет нулевого пересечения;
- запрет двух своих пересечений;
- запрет пересечения с противником;
- boundary conditions для занятых клеток;
- пустой padding за границей;
- легальность всех сгенерированных placements;
- точный формат `X Y\n`;
- возврат легального хода стратегией;
- ситуацию без доступных ходов;
- символы и placements Player 2.

Перед сдачей полезно выполнить:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test
```

## 🏆 Чек-лист аудита

Официальный аудит требует:

| Карта | Противник | Требование |
| --- | --- | --- |
| `map00` | `wall_e` | минимум 4 победы из 5 |
| `map01` | `h2_d2` | минимум 4 победы из 5 |
| `map02` | `bender` | минимум 4 победы из 5 |
| подходящая карта | `terminator` | бонус: минимум 4 победы из 5 |

Студенческий игрок должен быть проверен как в позиции `p1`, так и `p2`.

В README намеренно **не записан неподтверждённый win rate Rust-версии**. Стратегия перенесена с уже настроенной реализации, однако перед сдачей именно Rust-бинарник нужно заново прогнать через официальный Docker-аудит и только после этого зафиксировать фактические результаты.

## 🎬 Replay Lab

Каждый матч, запущенный из интерфейса, сохраняет сырой `.log` в `replays/`. После завершения матча браузер загружает этот же файл как обычный replay.

Возможности:

- live Canvas-отрисовка;
- drag & drop сырых логов `game_engine`;
- импорт/экспорт нормализованного Replay JSON;
- встроенный demo replay;
- Play / Pause;
- первый / предыдущий / следующий / последний ход;
- timeline;
- скорость `0.5×`, `1×`, `2×`, `4×`, `8×`;
- отображение текущей фигуры;
- счёт и график роста территории;
- локальная браузерная библиотека реплеев;
- превью финальной доски;
- сохранение сырых логов на диске даже при переполнении `localStorage`.

Для ручной записи реплея внутри `/filler` также есть helper:

```bash
sh /filler/solution/scripts/capture-replay.sh \
  -f maps/map00 \
  -p1 /filler/solution/target/docker-linux/release/filler \
  -p2 linux_robots/wall_e
```

## 🏗️ Архитектура

```text
                         official game_engine
                                 |
                         stdin / stdout
                                 |
                                 v
                    +-------------------------+
                    |       Rust player       |
                    | parser -> validator     |
                    | -> strategy -> X Y\n    |
                    +-------------------------+

 browser
    |
    | HTTP / SSE
    v
 +---------------------------+
 | Rust visualizer server    |
 | match presets / launcher  |
 +-------------+-------------+
               |
               | docker CLI
               v
 +---------------------------+
 | official filler image     |
 | linux_game_engine         |
 | Rust player + robot       |
 +-------------+-------------+
               |
        raw engine output
          /           \
         v             v
     SSE live UI    replays/*.log
         |             |
         +-------> Replay parser
                       |
                       v
                  Canvas playback
```

Игрок никогда не пишет debug- или visualizer-данные в `stdout`: там остаётся только игровой протокол. Диагностика отправляется в `stderr`.

## ⚠️ Примечания

- Официальный пакет сейчас использует `rust:1.63-buster`, поэтому player сохраняет совместимость с Rust `1.63` и не использует сторонние Rust-зависимости.
- Встроенный launcher компилирует Linux-player внутри официального образа, а не пытается линковать Linux-бинарник из Windows.
- Будущие фигуры случайны, поэтому стратегия не изображает детерминированный minimax по неизвестным будущим ходам.
- Если легального хода нет, программа возвращает `0 0\n`, как требует протокол задания: бот всё равно должен дать ответ.
- Visualizer по умолчанию слушает только `127.0.0.1` и предназначен для локальной разработки и аудита.
